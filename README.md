# 홈 스티밍 음원 라벨링

기존 Puffin 라벨링 화면에서 음원을 추가하고 구간을 편집한 뒤, **작업 저장**을 누르면 원본 녹음과 JSON을 비공개 GitHub 저장소에 함께 저장합니다. 과거 홈 음원·검수 자료도 같은 비공개 데이터 저장소에 통합되어 있습니다. 자동 분류·모델 학습·로컬 데이터 가져오기 자동화는 하지 않습니다.

- 웹사이트: https://pillkyu.github.io/Milk_Steaming_Labeling/
- 웹 코드: `pillkyu/Milk_Steaming_Labeling` (공개)
- 신규 음원·라벨: `pillkyu/Milk_Steaming_Labeling_Data` (비공개)
- 별도 유료 서버·데이터베이스·Git LFS·사용량 과금 서비스는 사용하지 않습니다.

## 접속과 사용자 초대

관리자는 **비공개 데이터 저장소**의 Settings → Collaborators에서 참여자를 초대합니다. 참여자가 초대를 수락한 뒤 각자 GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens에서 토큰을 발급합니다.

1. Resource owner는 `pillkyu`, Repository access는 데이터 저장소 하나만 선택합니다.
2. Repository permissions에서 **Contents: Read and write**를 부여합니다. Metadata 읽기는 기본 권한입니다.
3. 만료일을 설정하고 발급된 토큰을 사이트의 연결 창에 입력합니다.

GitHub 계정/저장소 소유 형태에 따라 외부 협업자에게 세분화된 토큰의 저장소 선택이 제공되지 않을 수 있습니다. 그 경우 아래의 외부 협업자 안내를 확인하세요. 토큰이나 비밀번호를 이 저장소에 커밋하지 마세요. 사이트는 토큰을 현재 탭 메모리에만 두며 새로고침하면 다시 연결해야 합니다. 토큰은 GitHub API로만 전송합니다.

**외부 협업자:** 개인 계정 소유 저장소의 외부 협업자는 GitHub의 fine-grained token 제한에 걸릴 수 있습니다. 해당 사용자는 본인 classic PAT의 `repo` 권한으로 연결할 수 있으나, 이 토큰은 다른 비공개 저장소에도 넓은 권한을 가질 수 있습니다. 짧은 만료일을 사용하고 사이트를 신뢰할 때만 사용하세요. 장기적으로 GitHub App 로그인으로 바꿀 때 이 수동 토큰 입력을 대체할 수 있습니다. 공용 관리자 토큰을 배포하지 않습니다.

GitHub Pages의 화면 코드는 공개지만, 로그인 전에는 음원·라벨을 읽을 수 없습니다. GitHub가 비공개 저장소 접근을 검사합니다. 데이터 저장소가 공개로 변경되면 사이트가 연결을 거부합니다. 협업자는 해당 데이터 저장소를 직접 읽고 수정할 권한도 갖습니다.

## 작업 순서

1. `녹음 파일 추가`로 M4A/WAV/MP3 등의 파일을 선택합니다. 원본은 변환하지 않습니다.
2. 파형 드래그 또는 `I`·`O`로 범위를 선택하고 라벨을 누른 뒤 `Enter`로 구간을 적용합니다.
3. **작업 저장**을 누르면 현재 녹음 원본과 적용한 라벨이 GitHub에 저장됩니다.
4. 검수가 끝났다면 **검수 완료**를 누릅니다. 미라벨과 사용 제외 구간을 임의로 정답으로 바꾸지 않습니다.

편집 중 적용한 라벨과 새 음원은 IndexedDB에 임시 보관합니다. 업로드 선택/구간 적용만으로 GitHub에 쓰지 않습니다. 새로고침 후 같은 계정으로 연결하면 임시 작업을 복구합니다. 브라우저 데이터 삭제·저장 공간 부족은 임시 작업을 잃을 수 있으므로 GitHub 저장을 완료하세요. 공용 컴퓨터에서는 사용 후 사이트 데이터를 지우세요.

`작업 백업`은 라벨·자료 메타데이터·미적용 구간을 JSON으로 내려받습니다(음원은 포함하지 않음). 저장 충돌이 발생하면 백업 후 `자료 메모·사용 제외 → 최신 저장본 불러오기`로 현재 음원의 최신 저장본을 불러올 수 있습니다. 이때 확인창을 승인하면 해당 음원의 로컬 임시 작업은 교체됩니다.

## 저장 형식과 수동 다운로드

비공개 데이터 저장소를 처음 `git clone`한 후 필요할 때 `git pull --ff-only`로 가져옵니다. 웹 코드 저장소와 다른 저장소입니다.

```text
recordings/<원본 SHA-256>/
  original.m4a      # 실제 업로드한 확장자, 원본 바이트 그대로
  record.json      # 원본 정보, 파형, 라벨, 검수 상태, 수정자·시각
```

`record.json`의 `source.duration`과 `review.segments[].start/end`는 원본 녹음 시작 기준 초 단위입니다. `originalSHA256`로 중복/원본 일치를 확인할 수 있습니다. `decodedSampleRate`는 브라우저가 파형 생성용으로 디코딩한 샘플레이트이며 **원본 파일의 샘플레이트를 뜻하지 않습니다.** 학습 전 Mac에서 원본을 디코딩하고 샘플 수·라벨 끝 시각을 확인하세요. 동일 세션의 여러 파일은 학습/검증 분리 전에 한 그룹으로 묶으세요.

기존 라벨 ID, 구간 전체 덮임, `airEvents`, `steamPresence`, `reviewed`, `excluded`, 청소 방출의 `non_steam + endSignal=steam_purge`를 유지합니다. 검수 완료와 사용 제외 여부를 확인한 뒤 로컬 학습 파이프라인에서 처리합니다. 이 웹사이트는 학습을 실행하거나 기존 로컬 데이터셋을 수정하지 않습니다.

## 제한과 검증

- 파일당 **20MiB·15분 이하**. 브라우저의 메모리와 디코딩 호환성을 위해 제한합니다. 지원 확장자여도 디코딩이 안 되면 저장하지 않고 안내합니다. WAV·MP3·M4A부터 사용하세요.
- GitHub API로 원본과 라벨을 하나의 커밋에 저장합니다. 동일 파일의 다른 수정이 있으면 덮어쓰지 않습니다. 한 번 저장할 때 여러 API 요청이 발생하므로 저장 버튼 횟수와 API 요청 횟수는 다릅니다.
- 저장량은 무제한이 아닙니다. 삭제해도 Git 이력에는 원본이 남을 수 있습니다. GitHub의 파일/저장소/API 제한 안에서 사용하세요.
- 페이지는 `site/`만 배포하며 데이터 저장소·토큰·개인 녹음은 배포하지 않습니다.

```sh
npm test
python3 -m http.server 8000 --directory site
# Playwright가 설치된 환경의 추가 브라우저 검사 (합성 음원·모의 GitHub 사용)
node tests/browser-check.mjs
```

브라우저 검사는 업로드·재생·구간 적용·임시 작업 복구·명시적 저장·검수 완료·재접속과 토큰 비저장을 확인합니다. 저장소 단위 검사는 비공개 접근 조건, 원본 해시, 라벨 검증, 동시 수정 및 원자적 저장을 확인합니다.

2026-11-11: 위 검사와 실제 비공개 GitHub 임시 브랜치에서 합성 음원 저장·라벨 수정·원본 다운로드 해시 일치 확인을 통과했습니다. 검증 브랜치는 제거했으며 `main`에 검증 음원은 넣지 않았습니다. 다른 사용자의 계정과 각 브라우저/녹음 형식 조합은 별도 확인이 필요합니다.

## 웹 코드 수정 후 배포

Pages는 `gh-pages` 브랜치의 루트를 사용합니다. 웹 코드 변경을 `main`에 커밋한 뒤 다음과 같이 `site/`만 배포합니다.

```sh
git push origin main
git subtree push --prefix site origin gh-pages
```

음원이나 라벨 저장에는 웹사이트 재배포가 필요 없습니다. 신규 자료는 비공개 데이터 저장소에서 연결 시 읽습니다.

화면은 홈 스티밍 전용입니다. 자료 그룹·종류 선택, 학습용 내보내기와 중복 백업 버튼을 제거했습니다. 작업 백업은 상단 한 곳에 유지합니다. 소리 라벨만 선택할 수 있으며 미라벨·구간 사용 제외·자동 후보 버튼과 단축키는 제공하지 않습니다. 아직 라벨링하지 않은 구간과 지운 구간은 데이터 내부에서 `unknown`으로 보존하며, 기존 저장 형식은 변경하지 않습니다.

## 저장 전 라벨 재확인

`작업 저장`과 `검수 완료`에서 소리 차이를 검사합니다. 의심 구간이 없으면 바로 저장하며, 의심 구간이 있으면 해당 구간 듣기·라벨/경계 수정·확인 후 저장을 안내합니다. 확인한 구간은 경계와 라벨이 같으면 다시 묻지 않습니다. 자동 삭제나 라벨 변경은 없습니다. 자료 부족은 미판정으로 남기고, 분석 실패·시간 초과 시 명시적으로 검사를 건너뛰어 작업을 저장할 수 있습니다.

- 브라우저 Web Worker에서 48kHz 모노, FFT 2048/hop 512, 기존 Chic 273개 특징을 계산합니다. 메모리를 제한하기 위해 구간당 최대 256개 프레임을 균등 표집해 중앙값을 사용합니다.
- 같은 라벨의 가까운 기존 구간까지 표준화 거리를 계산합니다. 원본별 대표값으로 스케일을 맞추고, 원본 하나씩 제외한 최대 점수들의 경험적 95백분위를 경고 기준으로 삼습니다. **오류 확률이나 α=0.05 보장을 뜻하지 않습니다.**
- 원본 5개 미만인 라벨은 소리 차이를 판정하지 않습니다. 0.5초 미만은 오류로 단정하지 않고 길이/경계 확인을 안내합니다. 둘 다 초기 운영 규칙이며 통계적 보장을 주는 기준이 아닙니다.
- 최초 비교 자료는 비공개 데이터 저장소의 `feedback/reference.json`에만 저장합니다. 공개 코드에는 실제 음원·라벨·특징 자료가 없습니다.
- 저장할 때 비공개 저장소의 최신 스냅샷을 읽습니다. 검수 완료 자료와 사용자가 재확인한 구간의 특징을 다음 비교에 반영합니다. 사용 제외·미확인 건너뛰기·현재 검사 중인 원본은 기준에서 제외하며, 기존 seed와 같은 원본은 최신 저장본을 우선합니다. 이관된 과거 검수 구간은 ID·라벨·경계가 그대로인 동안 비교 기준을 유지하며 수정·삭제·사용 제외하면 해당 기준을 제거합니다. 동일한 소리를 다시 인코딩한 파일은 SHA가 달라 별도 중복 정리가 필요합니다.
- `record.json`의 `review.feedback`에 알고리즘/특징 버전과 구간별 특징·판정 당시 Git 커밋·점수·기준·사용자 결정·시각·계정을 저장합니다. 라벨이나 경계가 변경된 구간의 확인은 무효화합니다. 기존 원본 및 학습용 라벨 구조는 유지합니다.
- 별도 Python 서버나 유료 서비스는 없습니다. 계산 속도는 사용자 기기에 따라 달라지며 90초가 지나면 검사 없이 저장하는 선택을 안내합니다.

검증: 단위 검사에 Swift에서 생성한 합성 음원 특징 정답을 포함했습니다. 로컬의 실제 원본 22개/165구간에서도 특징 수치가 일치했으며(최대 절대차 약 2.1e-10), 저장된 M4A 1개의 Chromium 디코딩도 같은 경고 판정을 냈습니다. Chromium 데스크톱/모바일 크기에서 재생·확인 전 저장 방지·수정/취소·재접속·재확인 유지·분석 실패 시 저장을 검사했습니다. 실제 휴대폰과 Safari, 통계적 오라벨 탐지율은 별도 검증이 필요합니다.

## 로컬 모델 학습

이 Mac의 기존 학습 자산과 비공개 데이터 저장소를 연결한 실행기는 [training/README.md](training/README.md)에 있습니다. `training/run.command`를 실행하면 pull → 데이터 검사 → 특징 추출 → 학습 → CoreML 내보내기 → 오탐 평가를 순서대로 처리합니다. 원본·모델·실행 결과는 공개 저장소 바깥에 보관하며, 웹사이트나 앱 모델을 자동 교체하지 않습니다.

## 과거 홈 자료 통합 (2026-11-13)

과거 로컬 홈 원음 22개와 라벨347구간을 비공개 데이터 저장소에 추가했습니다. 기존 업로드7개와 합쳐 사이트에서29개 원본·533구간을 열고 편집할 수 있습니다. 원음은 약29.9MiB이며 변환 없이 원래 M4A 바이트를 보존했습니다. 로컬 원본은 백업으로 남겨 두었습니다.

분할 녹음36은 원본646초 시간축으로 합쳤습니다. 기존540–600초가 미검수·미라벨이므로 이 파일 전체는 검수 중으로 남깁니다. 다른 미검수 원본1개도 상태를 유지하며, 임의로 검수 완료로 바꾸지 않습니다. 현재26개가 검수 완료·사용 가능,2개가 검수 중,1개가 사용 제외입니다.

앞으로는 이 사이트의 라벨을 편집하고 저장하세요. 학습기는 같은 원본의 GitHub 라벨을 우선하고 중복 학습을 방지하며 기존 원본의 검증 분할을 유지합니다. 검수 중인 파일은 전체 검수 완료 전까지 학습에서 제외됩니다. 이관 전후 모델 성능을 비교할 때에는 검수 상태와 평가 원본이 같은지 확인해야 합니다.

임시 localhost 통합 뷰어는 제거했습니다. 음원은 공개 Pages에 포함하지 않고 비공개 데이터 저장소에서만 읽습니다.
