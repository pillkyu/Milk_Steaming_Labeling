# 홈 음원 학습 파이프라인

현재 BillScanner Mac 작업공간용 실행기입니다. `run.command`를 실행하면 아래 단계를 순서대로 처리합니다.

```text
데이터 저장소 git pull --ff-only
 → 커밋 고정·원본 SHA256·라벨 검사
 → 검수 완료/사용 제외 반영·기존 홈 자료와 병합
 → 원본 단위 5분할·기존 특징 추출
 → 모든 분할 및 전체 자료 모델 학습
 → CoreML 내보내기·현재 앱 규칙으로 평가
 → 오탐 보고서·모델·단계별 실행 상태 저장
```

## 실행

터미널에서 이 폴더의 `./run.command`를 실행하거나 Finder에서 더블클릭합니다. GitHub CLI에 해당 비공개 저장소를 읽을 권한으로 로그인되어 있어야 합니다. 토큰은 코드나 실행 결과에 저장하지 않습니다.

```sh
./run.command                 # pull부터 학습·평가까지
./run.command prepare        # 다운로드·라벨/원본 검사까지만
./run.command features       # 특징·학습 테이블까지
./run.command train          # 모델 내보내기까지
./run.command evaluate       # 평가까지
./run.command --no-pull      # 현재 로컬 커밋으로 전체 실행
```

각 명령은 필요한 앞 단계도 실행합니다. 같은 데이터 커밋과 코드로 완료한 단계는 결과 파일의 해시를 확인한 뒤 재사용합니다. 실패한 단계는 `state.json`에 남기며 다음 실행에서 다시 시도합니다. 데이터 저장소에 로컬 수정이 있으면 자동 덮어쓰기나 강제 pull 없이 중단합니다.

결과는 웹 저장소 바깥 `BillScanner/TrainingRuns/HomeSteaming/runs/<데이터커밋>-<코드해시>/`에 저장됩니다. 가장 최근 성공 실행 경로는 `TrainingRuns/HomeSteaming/latest.json`에서 확인합니다.

| 파일 | 용도 |
|---|---|
| `REPORT.md` | 결과와 해석·한계 |
| `summary.json` | 정확도, 라벨별 FP/TP/FN/TN, 오탐 시간·연속 횟수, 종료 확인 요청 |
| `fp-by-source.json` | 원본별 오탐과 종료 확인 요청 시각 |
| `data-audit.json` | 파일별 포함/제외, 클래스별 구간 수 |
| `provenance.json` | 데이터 커밋과 학습·앱 코드 해시 |
| `state.json` | 단계별 실행 상태·소요시간·결과 해시 |
| `models/full/app/` | 전체 학습 자료로 만든 최종 후보 5개 CoreML 모델 |

## 데이터 정책

- 기존 홈 자료와 GitHub의 검수 완료 자료를 합칩니다. 사용 제외 파일은 넣지 않습니다.
- 동일 원본 파일이 다시 저장되면 최신 웹 라벨을 우선합니다. 사용 가능한 업로드를 디코딩한 PCM이 기존 원본과 같아도 중복을 제거합니다. 업로드끼리 PCM이 같으면 라벨 충돌을 확인하도록 중단합니다.
- 원본 파일이 다르게 인코딩되거나 부분 잘림된 중복, 같은 세션의 다른 파일은 자동으로 알아내지 못합니다. 현재 분할은 원본 파일 단위이며 세션 독립 평가라고 주장하지 않습니다.
- 미라벨·사용 제외 구간·현재 모델에 없는 끓는음은 학습과 정량 채점에서 제외합니다. 웹의 이상치 경고는 자동 제외 근거로 사용하지 않습니다.
- 웹에서 저장한 256프레임 요약 특징은 재확인용입니다. 학습은 원본에서 기존 모델 계약의 전체 특징을 다시 사용합니다.

## 모델·평가 계약

기존 `Analysis/HomeSteamingApp20261111`의 학습기를 재사용합니다. Gate→Air/Metallic, 273개 특징, Start와 1845차원 End 구조를 유지합니다. 기존 학습기는 명시적 원본 목록을 받는 `prepare_tables` 함수와 의존성 위치 설정만 분리했으며, 학습 설정은 변경하지 않았습니다.

현재 앱의 `ChicEndRule.swift`를 실행별로 복사해 사용합니다. 앱이 종료 여부를 묻고 분석을 계속하므로, **종료 확인 요청**과 자동 종료를 구별합니다. 앱 파일이나 앱의 모델 리소스는 변경하지 않습니다. 출력 후보도 자동 적용하지 않습니다.

정확도와 작업음 전용 혼동 행렬 외에, 알려진 비스티밍·시작·종료 구간까지 포함한 클래스별 오탐을 계산합니다. 미라벨은 오탐 분모에서 제외합니다. 프레임 단위 원시 분류와 실제 앱 알림은 별도입니다. 모델 문턱을 평가 자료에 맞춰 자동 조정하지 않습니다.

5분할 결과는 개발 평가이고, 전체 자료로 다시 학습한 최종 파일의 독립 테스트 성능이 아닙니다. 특히 같은 머신/마이크/세션의 연관성과 적은 배경음 정답이 남아 있습니다.

## 이 Mac의 의존성

- 작업공간의 `.venv-clap` Python 및 `.venv`의 FFmpeg
- Xcode/Create ML/Core ML, 기존 `Analysis/HomeSteaming20261111` 및 `HomeSteamingApp20261111`의 소스·네이티브 도구·기준 모델·원본 데이터
- 기존에 설치한 CoreML protobuf 의존성은 최초 실행 시 `TrainingRuns/HomeSteaming/dependencies`에 보존해 임시 폴더 삭제의 영향을 줄입니다.
- 현재 실제 앱 경로: 작업공간 옆 `ADA/2026-C6-A04-BEANDOONG`의 SoundAnalysis 코드

새 Mac에서 이 저장소만 clone하면 위 학습 자산까지 생기지는 않습니다. 이 실행기는 현재 로컬 작업공간을 연결한 것이며, 원본 데이터·모델·의존성을 공개 저장소에 포함하지 않습니다.

## Airflow 화면으로 실행

이 Mac의 `TrainingRuns/Airflow/.venv`에 Airflow 3.4.0을 별도로 설치했습니다. `./airflow.command`를 실행한 뒤 [로컬 Airflow](http://127.0.0.1:8088)에 접속합니다. 이미 실행 중이면 화면만 열면 됩니다. 중지는 실행한 터미널에서 Ctrl+C입니다.

1. `home_steaming_training`을 엽니다.
2. **Trigger**를 눌러 실행합니다. 자동 주기 실행은 설정하지 않았습니다.
3. **최신 음원 받기 → 원본·라벨 검사 → 특징 추출 → 모델 학습 → 오탐 평가·결과** 순서로 진행됩니다.
4. 각 단계의 **Logs**에서 진행 상황을, 마지막 단계의 로그와 **XCom**에서 성능과 결과 경로를 확인합니다.

CLI와 같은 Python/Swift 코드를 호출하고, 완료한 단계는 해시 검증 후 재사용합니다. 첫 단계에서 데이터·코드 버전을 고정하며 도중에 바뀌면 섞어서 학습하지 않고 실패 처리합니다. 실패 단계는 한 번 재시도하며, CLI와 Airflow가 동시에 학습 파일을 쓰지 않도록 잠금을 사용합니다.

이 화면은 로그인 없는 **이 Mac 전용 개발 서버**이며 `127.0.0.1`에만 연결됩니다. 외부 공유용 서버가 아닙니다. Mac과 Airflow가 켜져 있어야 실행되며, 학습은 기존 Mac 환경에서 수행합니다. Airflow 로그·DB도 공개 저장소 밖 `TrainingRuns/Airflow/home`에 남습니다.

설치를 재현하려면 Python 3.12 가상환경에 `apache-airflow==3.4.0`을 [공식 제약 파일](https://raw.githubusercontent.com/apache/airflow/constraints-3.4.0/constraints-3.12.txt)과 함께 설치합니다. 학습 Python 환경과는 분리합니다.

## 확인

BillScanner 폴더에서 `.venv-clap/bin/python -m unittest discover -s Milk_Steaming_Labeling/training -p 'test_*.py'`를 실행합니다. 테스트는 원본/세션 분리와 미라벨·끓는음이 음성 정답으로 섞이지 않는지 확인합니다. 실제 실행에서는 원본/라벨 무결성, 학습·평가 원본 분리, 모든 평가 모델의 앱 재생 결과 및 최종 CoreML 확률 일치를 검사합니다.
